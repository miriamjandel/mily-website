# Mily Personal Website

## Project purpose

This is a personal website for Mily.

The goal is to learn web development by building a real website gradually with Codex.

The website should feel personal, modern and visually interesting. It should not feel like a traditional CV, corporate profile or generic portfolio template.

Work and AI are important parts of the site, but running is also a major personal theme. Other parts of life may be added later.

## Current technology

Keep the project simple.

Current stack:
- HTML
- CSS
- Local image files

Do not introduce:
- JavaScript
- frameworks
- package managers
- build tools
- external libraries

unless explicitly requested.

Prefer the simplest solution that works.

## Current structure

The website currently has a main one-page site with:

1. Hero
2. About
3. Work
4. Running
5. Contact

Navigation links point to the relevant sections.

There is also a separate running page:

- `running.html`

The running page is for deeper RunWithMily content such as current focus, upcoming races and running bucket list ideas.

Images are stored in:

`images/`

## Design direction

The visual style should be:

- modern
- clean
- spacious
- editorial
- personal
- slightly creative
- visually polished without feeling over-designed

Use:
- generous whitespace
- strong typography
- warm neutral / off-white colours
- large imagery where appropriate
- subtle variation between sections
- asymmetric layouts when they improve the design

Avoid:
- generic portfolio templates
- CV-style layouts
- grids of cards
- excessive buttons
- unnecessary icons
- heavy gradients
- overly bold typography everywhere
- making every section use the same layout
- visual effects that feel like PowerPoint
- adding content simply to fill space

The website should feel designed rather than templated.

## Hero

The hero should remain simple and personal.

Current main message:

"Hi, I’m Mily."

"Building smarter ways of working — and always chasing the next finish line."

The hero currently includes a personal photo.

Do not substantially redesign the hero unless explicitly requested.

## About

Keep About short and personal.

It should introduce Mily as a whole person rather than act as a professional biography.

## Work

Work should reflect interests in:
- Finance
- digital transformation
- AI
- smarter ways of working

Do not turn this section into a CV, employment history or list of skills unless explicitly requested.

## Running

Running should feel more expressive and personal than the Work section.

It can use stronger visual storytelling, photography and more expressive typography.

The current design direction uses a more handwritten / slanted style for the "Running" heading.

Avoid making the section look like a sports statistics dashboard unless explicitly requested.

## How to work with me

I am learning while building this project.

When making changes:

1. Inspect the existing HTML and CSS first.
2. Preserve design decisions that are not part of the requested change.
3. Make focused changes rather than redesigning unrelated parts of the site.
4. Do not add new functionality or content unless requested.
5. Prefer small iterations over large redesigns.
6. Keep the website responsive.
7. Keep HTML semantic and CSS understandable.

For small changes such as text edits, it is useful to tell me where I can change them manually instead of always editing them for me.

When explaining code, keep explanations simple and practical.

## Design discussions

If I ask what might look better or ask for design ideas:

- discuss the options first
- give 2–3 clear directions when useful
- do not immediately modify the code unless I ask you to

If a design request is ambiguous, prefer discussing it before making a major visual change.

## Code changes

Do not refactor working code just for the sake of refactoring.

Do not change unrelated sections when working on one specific section.

After making a meaningful change, briefly explain:
- what changed
- which file(s) changed
- anything useful for me to understand or test

Keep file and folder names web-friendly and consistent.
